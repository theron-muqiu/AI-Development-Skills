# 技术设计

输入本需求的需求分析及已确认材料。默认产出 `ai-devlop-plan/详细设计.json`、`接口设计.json`、`数据结构设计.json`，每份生成前完整读取同名 Schema 和示例。沿用需求编号和场景 ID；缺失稳定场景编号先补前置条件，不在设计中另造。只要求某份时只更新指定文件并说明关联影响。

定向检查相关代码、接口、数据和项目规范，区分现有行为与拟新增设计。影响业务结果的缺口先澄清，技术选择在项目约束内确定。接口写稳定 ID、方法路径、参数约束、返回、权限、错误、示例和场景引用；不为补齐 CRUD 增加功能。数据写字段类型、可空、默认值、索引顺序与用途、关系是否为物理外键；默认值区分 unset/null/literal/expression，Redis 与 MQ 只在实际涉及的时候保留。

详细设计按场景连接实现入口、接口、数据结构和计划验证方式；场景专属逻辑在场景设计中说明，共用行为在模块设计中说明，但不因此主动抽取代码方法。按需说明事务、并发、幂等、外部失败及迁移影响。设计不能冒充已实现或已验证。当前 Agent 顺序完成，不创建子代理，不编写业务代码、执行迁移或发布。

## JSON 文档约定
先读取 `ai-devlop-spec/assets/文档格式.md` 的公共约定，再读取本技能 assets 下对应的 JSON Schema 与同名完整示例。示例只展示结构，不代表实际业务约定。JSON 使用 UTF-8、两空格缩进、英文属性名；说明文字可用 Markdown，图表保留 Mermaid。跨文档引用使用相对文件路径与稳定实体 ID；没有内容的集合用空数组。已有文档先读取再定向修订，保存前检查外部变更。

完成本轮文档修改后执行 `ai-devlop docs validate <需求目录>`，通过后执行 `ai-devlop docs render <需求目录>`，交付 JSON 与 `index.html`。源码环境可用 `uv run ai-devlop docs ...`；未长期安装 CLI 时，可经 `uvx --from "git+https://github.com/theron-muqiu/AI-Development-Skills.git@v0.4.0rc1" ai-devlop docs ...` 调用预发布版；正式版 v0.3.2 不支持此命令。校验或渲染失败时不得声称已同步完成，旧 HTML 仍是旧快照。
