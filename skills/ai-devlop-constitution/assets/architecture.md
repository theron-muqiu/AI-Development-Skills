## 规则填写格式

以下每条规则按五字段填写，Rule ID 在工程、架构、安全规范间保持唯一且稳定：

| 字段 | 内容 |
| --- | --- |
| Rule ID | [唯一编号，如 ARC-001] |
| Strength | [MUST / MUST NOT / SHOULD / MAY；SHOULD 写明偏离条件] |
| Scope | [适用范围] |
| Requirement | [明确、可执行的具体限制与指导] |
| Verification | [验证方式] |

## Architecture Style

[直接说明当前系统采用的组织与运行形态及其边界限制。]

## Layer Boundary

[直接限制各层级或职责边界的入口、允许调用方向与禁止越界行为。]

## Module Boundary

[直接限制真实模块的职责划分、公开入口、私有实现及跨模块访问方式。]

## Dependency Rules

[直接限制模块间允许与禁止的依赖方向、循环依赖处理及外部依赖封装边界。]

## Data Ownership

[直接限制数据实体、存储与状态的归属权、读写权限及跨边界访问方式。]

## API Contract

[直接限制对外接口（HTTP/CLI/库/事件等）的契约归属、兼容性、版本与错误语义。]

## Transaction Boundary

[直接限制业务操作的原子性与一致性边界、提交/失败语义及跨边界副作用处理。]

## Integration

[直接限制外部系统或内部集成点的协议契约、信任边界、超时及异常/重试处理。]

## Extensibility

[直接限制已知扩展点的接入方式与兼容约束，禁止为未知需求过度抽象。]

## Architecture Testing

[直接限制架构边界、依赖方向与契约兼容性的检查方式及失败处理。]
