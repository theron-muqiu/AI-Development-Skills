# 项目宪法（constitution）

根据项目实际情况创建或修订两级规范，以明确、可执行、无冗余的规则直接约束和指导 AI 开发：L1 定义跨专业根本原则，L2 分别定义工程、架构和安全约束。

## 固定产物与优先级

先确定项目根目录；多仓库或路径不明时先询问。所有产物固定在项目的 `.ai-dev/memory/`：

| 层级 | 文件 | 职责 |
| --- | --- | --- |
| L1 | `constitution.md` | 5–8 条跨专业长期根本原则与适用优先级 |
| L2 | `engineering.md` | 工程结构、编码、测试、构建与交付约束 |
| L2 | `architecture.md` | 系统风格、模块边界、依赖与数据/契约约束 |
| L2 | `security.md` | 身份、权限、数据保护与安全验证约束 |

- 外部强制法律、监管与安全义务优先于项目内部规范。
- L1 高于 L2；L2 不得放宽、规避或取代 L1 的明确要求，也不得用 L1 宽泛原则机械否定有项目事实支撑的 L2 规则。
- L2 之间发生冲突时直接报告冲突条款与影响，等待用户决定，不自行择利或擅自改写其他规则。
- 实际代码只是现状证据，不自动凌驾于已明确的项目规范。

## 执行边界

- 当前 Agent 顺序执行，先读后改。只读咨询仅在会话中交付；明确创建或修订请求才写入授权文件。
- 只维护上述四份文件，不新增治理文件、变更日志、版本历史或审批记录，不生成业务代码。
- 不自动提交、创建分支、部署、安装依赖或调用后续开发技能，不修改需求、设计或任务文档。
- 既有文件完整读取后定向修订，保留未受影响的有效规则，不用模板覆盖已有内容。
- 各文件独立成文，直接说明本规则限制什么、要求什么，不在文件间相互引用或堆砌背景说明。

## 工作流程

### 1. 读取现状与原文件

1. 读取项目说明及 `.ai-dev/memory/` 下的现有四份文件；缺失部分明确记录。
2. 有针对性地读取构建配置、目录结构、入口模块、测试/CI 配置与安全配置，只查与规则直接相关的内容，不复制真实密钥或个人敏感数据。
3. 首次创建时读取本技能 `assets/` 下对应模板；模板中的占位提示需替换为项目真实约束，不把模板占位当作项目事实。
4. 首次初始化 `security.md` 时，可读取通用代码级安全预设 `assets/presets/security-baseline.md`（不限语言与框架），结合项目实际入口与数据敏感性裁剪落地；若项目技术栈匹配内置语言预设（当前提供 `assets/presets/java-spring-boot.md` 覆盖 JDK 17+ / Spring Boot 3.x / MyBatis-Plus / Redis 单体与分布式双模，以及 `assets/presets/vue-ts-vite.md` 覆盖 Vue 3 + TypeScript + Vite + Pinia + Vue Router 前端工程），可读取对应预设作为初始化基线：Java 项目先确认单体还是分布式模式，再按实际仓库结构、组件与约束裁剪或标记待确认，禁止在不匹配的技术栈上硬套预设。

### 2. 澄清关键缺口

仅在缺失信息会显著改变规范边界（如项目根目录、核心架构风格、认证与数据边界、关键合规要求）时向用户提问；已有明确答案不重复确认，未知技术约束不编造。

### 3. 分层编写

- **L1（`constitution.md`）**：保持 5–8 条长期根本原则，每条写清稳定编号、约束内容与判定标准；不写具体技术栈、框架、目录或工具命令。
- **L2（`engineering.md`、`architecture.md`、`security.md`）**：保留各领域指定章节（不适用章节保留标题并简述原因；未知项标待确认），每条规则采用精简五字段，直接说明限制与做法：

| 字段 | 填写要求 |
| --- | --- |
| 规则编号 | 唯一且稳定的编号（如 `ENG-001`、`ARC-001`、`SEC-001`），三份 L2 间不重复，正式使用后不随意重编号 |
| 约束强度 | `MUST` / `MUST NOT` / `SHOULD` / `MAY`（`SHOULD` 写明偏离条件） |
| 适用范围 | 适用范围 |
| 具体要求 | 明确、可执行的具体限制与指导，不写空泛口号或跨文件引用 |
| 验证方式 | 如何验证遵守该规则 |

- **工程规范**：`编码规范` / `代码质量` / `测试规范` / `依赖管理` / `错误处理` / `日志规范` / `构建规范` / `持续集成与交付` / `文档规范`。
- **架构规范**：`架构风格` / `分层边界` / `模块边界` / `依赖规则` / `数据归属` / `接口契约` / `事务边界` / `外部集成` / `扩展性约束` / `架构测试`。必须基于真实模块、依赖与边界，不套用通用模式清单。
- **安全规范**：`身份认证` / `权限控制` / `数据隔离` / `敏感数据` / `输入校验` / `安全通信` / `审计日志` / `依赖安全` / `安全错误处理` / `安全测试`。直接针对真实信任边界与敏感数据类型制定限制。

### 4. 保存与一致性核对

- 确认只写入授权文件，模板占位符已替换为真实约束或标明待确认。
- 检查规则编号是否唯一、L2 是否违反 L1、L2 之间是否存在冲突，以及各文件是否保持独立无跨文件引用。
- 保存前后核对原文件，确保未误删其他有效规则。

## 交付

简明列出本次创建/修订的文件、L1 核心原则摘要、关键 L2 约束、内部一致性检查结果及仍需用户确认的缺口；不自动进入下游开发阶段。
