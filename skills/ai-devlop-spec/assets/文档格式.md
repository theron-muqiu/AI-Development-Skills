# 结构化需求文档格式 1.0

本文件是七类 JSON 文档的公共编写约定；每类字段和必填要求以相邻的 `*.schema.json` 为准。同名 `*.json` 是贯穿流程的结构示例，示例中的业务值不能照搬。Schema 与模板由仓库 `skills/` 单一来源维护，安装时分发到 Codex 或 Hermes。

## 文件与版本

一个需求目录包含 `原始需求/原始需求.json`、`ai-devlop-spec/需求分析.json`、`ai-devlop-plan/` 下三份设计 JSON、`ai-devlop-task/任务清单.json` 和 `ai-devlop-implement/实现记录.json`。阶段未开始时可以没有对应文件。

顶层固定有 `$schema`、`schemaVersion`、`documentType`、`requirementId`、`title`。`$schema` 使用 `ai-devlop://schemas/<documentType>/1.0`，由本地 CLI 解析，不访问网络。`schemaVersion` 当前为 `1.0`，与 CLI 发行版本独立。文本使用 UTF-8，保存时用两空格缩进。未知格式版本应由 CLI 报错，不静默处理。

## 实体与引用

实体 ID 在所属文件中唯一、长期稳定。需求场景沿用 `S-001`，任务沿用 `T001`；接口、数据、验收、输入和验证项也应有稳定 ID。新增使用该类已知最大编号之后的新编号；调整顺序或名称不重排，删除编号不复用。引用形如 `{ "path": "../ai-devlop-spec/需求分析.json", "id": "S-001" }`，相对路径从当前文件所在目录计算，必须归属于同一需求。引用来源材料时可加 `locator` 指明章节、页码或时间记录，外部材料还可加 `url`。展示器据此生成跳转，不使用章节序号作为关联依据。

需求结论的 `sourceRefs` 必须指向可定位的原始输入记录；附件在原始输入记录中保存相对路径与来源，正文不嵌入。原始输入记录保留真实用户原文、时间、时间来源、技能、类型及必要问题上下文。无法确认的业务结论不得写入正式需求。

## 内容与状态

编号、关联、字段、状态和结果使用结构化属性；解释正文可用 Markdown，图表存 Mermaid 源文本。Markdown 禁用原始 HTML；浏览器展示前清理内容。空集合写 `[]`，不适用的可选属性省略，不用占位字符串冒充事实。

任务当前状态为 `pending`、`in_progress`、`blocked`、`completed`。实现记录保存按时间追加的任务事实及验证事实；验证结果为 `passed`、`failed`、`not_run`。任务重开时保留原记录并注明原因，最新任务记录与清单状态一致；设计中的计划验证方式不得写成实际执行结果。

数据字段默认值用 `kind` 区分 `unset`（没有默认值）、`null`（显式 NULL）、`literal`（固定值）和 `expression`（数据库表达式）。后两类必须携带 `value`。接口示例保持 JSON 原始类型；阅读器使用无损 JSON 解析显示大整数。

## 校验与阅读

`ai-devlop docs validate <需求目录>` 只读校验，`--format json` 输出机器可读诊断；`--document <文件>` 可重复指定需求目录内自定义位置。`ai-devlop docs render <需求目录>` 先校验，成功才原子替换需求目录的 `index.html`。HTML 是生成时快照，不回写 JSON。旧 Markdown 需求按旧格式修订；需要迁移时逐项转换，验证后以 JSON 为维护源，保留旧文件。
