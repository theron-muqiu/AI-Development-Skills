# 需求分析

默认产出 `docs/requirements/<需求编号>/ai-devlop-spec/需求分析.json` 与同一需求的 `原始需求/原始需求.json`。完整读取本技能四份 JSON Schema 和示例。需求编号优先用本次用户明确指定值，其次材料中的编号；已有需求沿用旧编号。无编号时按用户时区当天生成 `XQYYYYMMDD-XXX`，从 001 查找空闲目录，不覆盖其他需求。编号冲突或需求归属不明时先澄清；自定义完整路径按用户指定。

原始输入按真实时间正序追加，保留用户原文，不以摘要替代。取不到消息时间时用实际保存时间并记录来源；简短选项回答保留理解所需问题上下文。附件存 `原始需求/输入文件/`，副本以时间戳加原文件名命名，重名追加序号；JSON 只记相对路径和原来源，不嵌入文件、不改来源文件。历史输入保留，敏感值脱敏并注明；用户明确禁止写文件时遵守。

先核对业务术语、目标、范围、规则、正常流程、异常边界和可观察验收结果。会改变业务结果的缺口先澄清，未确认内容不写成结论。场景按业务行为编号 `S-001` 起，新增编号不复用、不重排。术语、范围、规则、场景、步骤、异常、验收和状态变化逐项用 `sourceRefs` 指向可定位的原始输入或材料；现有代码只证明现状。当前 Agent 顺序完成，不创建子代理，不实施业务代码。

## JSON 文档约定
先读取 `ai-devlop-spec/assets/文档格式.md` 的公共约定，再读取本技能 assets 下对应的 JSON Schema 与同名完整示例。示例只展示结构，不代表实际业务约定。JSON 使用 UTF-8、两空格缩进、英文属性名；说明文字可用 Markdown，图表保留 Mermaid。跨文档引用使用相对文件路径与稳定实体 ID；没有内容的集合用空数组。已有文档先读取再定向修订，保存前检查外部变更。

完成本轮文档修改后执行 `ai-devlop docs validate <需求目录>`，通过后执行 `ai-devlop docs render <需求目录>`，交付 JSON 与 `index.html`。源码环境可用 `uv run ai-devlop docs ...`；未长期安装 CLI 时，可经 `uvx --from "git+https://github.com/theron-muqiu/AI-Development-Skills.git@v0.4.0rc1" ai-devlop docs ...` 调用预发布版；正式版 v0.3.2 不支持此命令。校验或渲染失败时不得声称已同步完成，旧 HTML 仍是旧快照。
